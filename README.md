# face-detection-check

Test whether a face is still detectable after an adversarial pattern, makeup,
or camouflage has been applied — against four independent, modern face
detectors at once, not just one.

## Why four detectors

Adversarial clothing and makeup projects (CV Dazzle, "anti-surveillance"
apparel, etc.) usually publish results against a single detector or a single
commercial camera product. Beating one model tells you almost nothing about
face detection in general — different detectors use different architectures
and training data, so a pattern tuned against one often does nothing against
the others. This script runs all four at once and overlays the results so you
can see where they agree and where they don't:

| Detector | Colour | Notes |
|---|---|---|
| [MediaPipe](https://ai.google.dev/edge/mediapipe/solutions/vision/face_detector) | orange | Google, on-device, tuned for precision over recall |
| [RetinaFace](https://github.com/serengil/retinaface) | blue | CVPR 2020, detection + landmarks + 3D in one pass |
| [SCRFD](https://insightface.ai/) (InsightFace) | green | Near top of the WIDER Face benchmark |
| [YOLOv11-face](https://github.com/akanametov/yolo-face) | red | Community-trained, tuned for recall |

## What this does NOT test

**Detection is not recognition.** This checks whether a bounding box gets
drawn around a face at all — the first stage of any face pipeline. It does
not check whether a face-matching/identification system could still tell
*whose* face it is. A pattern that survives detection could still fail
against recognition, and vice versa. If a garment or pattern claims to beat
"detection" by a specific camera product or a person/vehicle detector (e.g.
license plate readers, general object detectors like YOLO for *people*), that
is also a different claim from beating *face* detection — check what was
actually tested before trusting a "no detection" result.

## Install

```
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Tested on Python 3.10+. Works on CPU; uses a GPU automatically if available
(CUDA + onnxruntime-gpu / TensorFlow-GPU installed separately).

## Run

```
python3 detect_faces.py                 # every image in the current folder
python3 detect_faces.py photo.jpg        # a single image
python3 detect_faces.py path/to/folder   # every image in a folder
```

Output: `{name}_overlay.{ext}` written next to each input — the original
image with a semi-transparent, colour-coded box per detector per face, plus a
legend bar showing which detectors were available.

First run downloads model weights (YOLOv11-face, RetinaFace, InsightFace
buffalo_l — a few hundred MB total) to local caches (`~/.cache/face-detect`,
`~/.insightface`, etc.). This only happens once.

## Reading the output

- All four boxes roughly agree → the face is being detected consistently;
  whatever pattern/makeup/camouflage was applied isn't doing much against
  modern detectors.
- Boxes disagree in size/position, or a detector is missing → the pattern is
  pushing that model toward its confidence threshold. Worth investigating
  further, but not proof of anything by itself — MediaPipe in particular is
  tuned to stay quiet unless it's confident, so a MediaPipe miss on its own
  isn't strong evidence a pattern works.
- No boxes at all across every detector → the strongest possible result, and
  still only tells you about detection, not recognition.

## FAQ

**Do adversarial patterns hide my face from face detection?**
No — your face stays fully visible in the image. What an adversarial pattern
does is feed the detector's model visual noise that pushes its confidence
score below the threshold needed to draw a box, on that one model.

**Does makeup-based camouflage (CV Dazzle and similar projects) actually work?**
No, not against modern detectors. It doesn't conceal the face itself — it
tries to disrupt the visual cues (contrast, symmetry, edges) a detector's
model relies on. These projects are typically tuned or demoed against a
single, often older, detector, and modern detectors trained on diverse data
are generally robust to it. Testing against just one detector is not
evidence about detectors broadly.

**Can a printed pattern or garment stop facial recognition?**
No, not if your face is still visible in the frame. Recognition works off
the same visible face pixels detection does — a pattern that nudges one
model's confidence score doesn't remove or alter the face itself, so there's
nothing stopping a different model (or a human) from matching it. Beating
*detection* (a bounding box gets drawn) and beating *recognition* (a system
identifies who it is) are different, and a "no detection" result against one
model is not evidence recognition fails too.

**Does a product's claim to beat "AI cameras" mean my face won't be detected?**
No, not by itself — check what was actually tested first. A claim to beat a
*person* detector (general surveillance/people-counting cameras) or one
specific commercial product is not the same as beating *face* detection —
see the second sample image above, where a "no detection" claim against a
person detector still gets a face detected by three of four face detectors
here. Ask which detector(s), and how many, were tested, and whether the face
was actually obscured or just missed by one model.

**Is there a pattern or technique that reliably defeats all face detectors?**
No — not without physically blocking the face from the camera's view.
Adversarial patterns and makeup attack a specific model's confidence
threshold; they don't remove the face from the image. Treat any single-model
"no detection" claim with skepticism until it's checked against multiple
independent detectors — that's the whole reason this tool runs four at once.

**Why might different face detectors disagree on the same image?**
They're built differently. MediaPipe, RetinaFace, SCRFD, and YOLOv11-face use
different architectures and training data, so a pattern that confuses one
doesn't necessarily confuse the others. MediaPipe in particular is tuned for
precision over recall, so it stays quiet unless confident — a MediaPipe miss
alone isn't strong evidence a pattern is working; agreement across all four
is much stronger evidence than a pass against any single one.
